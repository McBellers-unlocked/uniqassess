## Bounded first-pilot target

The proposed implementation remains the [AWS cloud lab plan](AWS_CLOUD_LAB_PLAN.md): one exclusive account per active candidate; `eu-west-1`; a fixed Lambda application, private S3 data/artifacts and CloudWatch evidence; Terraform and a real recorded release pipeline. Two simultaneous AWS candidates require two independently leased accounts. Cloud accounts must not contain assessment records, production secrets or unrelated applications.

Before enabling Task 2, verify these controls with real allowed and denied API calls:

- Issue only a protected, short-lived candidate role; keep cleanup/orchestration identities outside candidate execution. Never install the observed root credentials in a runner.
- Deny unrelated services, regions, identity creation, cross-account grants and changes to protected boundaries, trust, logging, time controls and reserved concurrency. Scope `PassRole` to the fixed application role and Lambda.
- Keep all four S3 Block Public Access settings enabled at the sandbox account and bucket levels, protected from candidate changes. Default bucket settings alone are not the complete control. [S3 Block Public Access](https://docs.aws.amazon.com/AmazonS3/latest/userguide/access-control-block-public-access.html)
- Check the new account's actual Lambda quota before depending on a reserved-concurrency limit. AWS leaves 100 units for unreserved functions; a low-quota new account may require an increase before a fixed limit of one can be configured. Reserved concurrency bounds simultaneous execution, not cumulative requests, logs or total spend. [Lambda reserved concurrency](https://docs.aws.amazon.com/lambda/latest/dg/configuration-concurrency.html)
- Run long operations as durable asynchronous jobs; preserve evidence across disconnection/retry; measure copied-credential denial after expiry; inventory and remove all permitted resources independently of Terraform state. Quarantine uncertain accounts instead of reassigning them.
- Set budgets and alerts as a secondary control; billing updates are delayed, so these are not a real-time spending cap. Actual account/pipeline charges and cleanup costs remain unmeasured. [AWS Budgets best practices](https://docs.aws.amazon.com/cost-management/latest/userguide/budgets-best-practices.html)

The dedicated-account dependency is resolved. The existing Kubernetes isolation and cleanup evidence does not validate AWS controls. Live AWS candidate testing, credential revocation, account reset, load testing and cost measurement remain separate acceptance work. Account creation and a successful read-only probe do not imply that Task 2 is ready for candidates.

## Controlled-pilot network and cost limits

The current runtime creates an AWS-managed CodeBuild Linux container with privileged mode disabled, one concurrent build, and a five-minute build timeout. It does not configure a VPC, an outbound proxy or an AWS-endpoint allowlist. Candidate jobs can access public internet endpoints, including sources used to obtain Terraform and its provider. This is an internet-connected controlled pilot, not an AWS-endpoints-only execution environment. The management application's credentials are not delivered to the child account; IAM/account isolation and protected lease expiry are separate controls from network filtering. An outbound allowlist would require additional networking and artifact delivery work before claiming that property. [Current project creation](../infra/aws-labs/runtime/handler.py)

Resource, concurrency and lease limits reduce exposure but do not implement a precise currency spending cap. Candidate-controlled logs can produce CloudWatch embedded metrics with only `logs:PutLogEvents`; removing `cloudwatch:PutMetricData` alone does not prevent that. Distinct metric dimensions can increase charges, alongside log ingestion and storage. Actual per-assessment cost and worst-case request/log-volume exposure remain unmeasured; keep the account exclusive to a supervised pilot and reconcile usage before wider rollout. [CloudWatch embedded metric permissions and charges](https://docs.aws.amazon.com/AmazonCloudWatch/latest/monitoring/CloudWatch_Embedded_Metric_Format.html)
